## 本轮结果

同一组数据另提供[离线 HTML 可视化报告](2026-10-08-mcp-benchmark.html)，可切换统计值、点击工具查看阶段及查看逐次样本。此报告为本轮结果的单独转换，当前压测脚本仍按使用文档输出 TXT／JSON／JSONL。

直接截图有一次约 5.223 秒的长尾，因此平均值明显高于中位数；不能从本轮部分 a11y 工具均值低于截图就推断其总是更快。get_current_focus 等也有长尾；全部保留，没有删掉慢样本。十个样本的 p99 是最大值，尾部估计仍需更多样本；工具间的波动差异不意味着共享采集代码具有固定的速度排序。

## 实施与验证

- 复用 `image.capture`、`tool_timing` 和现有截图压测的统计函数；采用项目已安装 MCP 1.30.0 的公开客户端 API，无新增依赖。
- 新增专用离线自检，实际观察 RED→GREEN，覆盖计时块归属、预热／失败排除、同轮配对、空样本、业务错误与报告边界。
- 首次实跑暴露 Windows CRLF 解析问题；补回归确认 RED，统一换行后 GREEN。旧样本及原始日志保留，未用它们冒充成功统计。
- 随后在动态 launcher 的 80 次正式调用成功，但像素指纹变化，脚本返回 1 并标记不能作严格同场景比较；这组记录保留为诊断数据。
- 静态设置页是人工验证准备：只经已观察到的 Open Settings 入口进入，没有更改设置项。压测脚本本身不发送按键。静态页最终前后像素完全一致，且原 Home 焦点已恢复。
- 编译、pyflakes、专用离线自检、现有完整 1155 条自检及 `git diff --check` 均通过；四种非法参数／已有输出目录均在设备采集前返回 2。
- 88 个成功调用的原始日志切片逐项核对，工具名、总时间和阶段时间与样本一致；汇总另从逐次记录重算核对。
- 既有生产漂移修复与树回归文件哈希不变，保留原用户配置和其他本地修改。新增及更新范围为脚本、专用测试、使用文档、README 入口和本交付报告。
