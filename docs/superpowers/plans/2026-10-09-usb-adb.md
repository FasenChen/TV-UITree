**Goal:** CLI、MCP 和默认设备配置可以通过 ADB 设备序列号使用 USB 有线连接，现有网络连接保持兼容。

## 行为约定

1. 所有实时 CLI 命令增加 `--serial USB_SERIAL`；五个读取 MCP 工具增加可选 `serial`。使用 `adb devices` 中完整序列号，必须对应状态为 device 的目标。
2. `config.json` 可增加 `"serial": "USB_SERIAL"`。非空 serial 表示默认按序列号连接；网络字段可以继续保存，USB 模式不要求或校验 IP/port。
3. 优先级：显式 serial > 默认配置；显式 IP 或 port > 配置 serial；无显式目标时优先配置 serial，否则用已有 IP/port。显式 serial 与显式 IP/port 同时出现时报错。
4. serial 必须是非空字符串，不含空白、控制字符或冒号；拒绝将 IP:port 填入 USB 字段。显式空字符串不作为“未指定”。serial 为 null 或缺失则走网络默认值。
5. `--no-connect` 继续只控制网络 adb connect；不会让网络目标改选 USB。USB 自动连接与重连行为复用底层现状，不新增拔插重试。
6. `set_default_device` 支持 serial 或 TV_IP_Address 二选一。保存 serial 保留旧 IP/port 和其他配置；保存 IP 时删除 serial，port 省略则保留旧端口。单独 port、空目标、两种目标混用均拒绝，且配置字节不变。
7. 默认设备工具的 previous/current 在网络模式继续返回 `{TV_IP_Address, port}`，序列号模式返回 `{serial}`；config_path 不变，仍原子保存。MCP 写配置参数继续 strict 校验。
8. 连接失败的 CLI 提示按目标区分：USB 检查数据线、USB 调试、授权及 adb devices；网络保留现有提示。明确序列号时，其他在线设备不能代替离线或未授权目标。
9. `scripts/bench_mcp.py` 是共享服务消费者，增加 `--serial` 并将选定序列号传给直接截图与 MCP；网络专用的 bench_screencap.py 接口不改。
